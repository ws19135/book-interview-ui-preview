## 引導動線（2026-09-06 加）

同事不用自己想先點哪個。入口頁把三個功能排成 ①②③，
下一個該走的會標「建議接下來走這個」，走完自動打勾。

```
入口頁 ①②③ ──► 前情提要 ──► 階段 1…N ──► ★ 小結頁 ──┐
   ▲                          （階段清單全程可見          │
   │                            走過的可以點回去）        │
   └───────────── 接著走下一條 ◄────────────────────────┘
                              三條都走完 ──► 最後四題
```

- **階段清單**：每一階段都看得到全部步驟，走過的打 ✓ 且可點回去，現在這一步紅底線。
- **小結頁**：每走完一條，先告訴你「剛剛完成了什麼」，再帶你接下一條。
- **需求一進來就帶著對方想上的節目**（標「◆ 對方想上」），第 2 階段的「審核」才有東西可審。
  ⚠️ 那只是**標示**，⛔ 不會替使用者預先勾選——每個畫面初次進入都必須是未操作狀態。

## 追蹤深度依案件性質分流（Owner 裁定選項 1）

```
節目費用「不需要」  ── 一般互訪 ── 約好時間 → 勾「已發行事曆」──✂️ 到這裡交出去，⛔ 不追錄音上架
節目費用「可能／需要」── 付費上節目 ── 約好時間 → 錄音 → 剪輯(自己/外包) → 上架 ── 追到底
```

- 逐節目判定，資料在階段 2／3 就有，⛔ 不多問承辦人一個問題。
- 階段 6：一般互訪的集在時間定了之後出現「已發行事曆給雙方」勾選；「另外確認」中不能發。
- 階段 7：一般互訪的集不畫製作按鈕，只剩素材；「還差什麼」清單只列行事曆。
- 結案檢查「每一集都已上架或不予上架」改為「每一集都追到該追的地方」，兩種各看各的；外包項只看付費集。
- ⏸ 日曆串接真做的時候，「已發行事曆」會變成自動完成的動作。

## 每次打開都是全新的一輪

同事回報「打開會看到之前操作的留存」。原因是預覽稿曾經替使用者**預先勾好**兩個節目
（階段 2 與預告登記第 2 階段），看起來像上一次留下的。已修正：

| 概念 | 欄位 | 初始值 |
|---|---|---|
| 對方來文提到想上的節目（唯讀資訊） | `theirWish` | 有兩筆，只做「◆ 對方想上」標示 |
| 出版社在預告登記自己勾的 | `wish` | **空** |
| 經紀人放進名單的 | `picked` | **空** |

- 重新載入＝全新一輪：`doneTracks`、操作紀錄、各階段狀態都在記憶體，不寫任何儲存。
- ⛔ 不寫 cookie、⛔ 不寫 sessionStorage、⛔ 不寫 IndexedDB。只有回饋寫 localStorage。
- 開場頁如果偵測到這台電腦存著上次填的回饋，會**明講幾則並提供一鍵清除**。
- 看板的示範書單標明是內建資料，不是別人測試留下的紀錄。

```

 ├─ 新書訪談邀約（8 階段）
 │   1 建立需求與指定承辦     →  2 審核想上的節目並補推薦
 │   3 處理費用或例外審核     →  4 雙方確認節目名單
 │   5 記錄節目邀約回覆       →  6 逐節目確認製作方與訪談時間
 │   7 逐節目追蹤錄音上架素材 →  8 完成案件並查看歷程
 │
 ├─ 新書預告登記（5 階段）
 │   1 登記新書 → 2 勾選想上的節目 → 3 已經有人在等
 │   4 書況有變 → 5 通知受影響的人
 │
 └─ 即將出版新書（1 頁）
     依上市月份排序 · 顯示希望的兩個檔期與在等的節目數 · 一鍵轉成訪談需求
```

## 逐節目的分流

```
這一集由誰做？
 ├─ 公司統一發包 ─┬─ 剪輯發公司內部做      → 自己剪 → 上架
 │                └─ 不勾（＝發外包）      → 建立外包交辦單
 │                                            待處理→已收到→處理中→已完成 → 上架
 └─ 訪談節目自己處理                        → 交給節目方上架
```

⭐ 外包交辦的資料結構**正式系統已經有了**（交辦對象／用途／期望完成日／狀態），
缺的是這個勾選與實際串接。邊界維持：只存不透明的外部編號，⛔ 不讀寫外包系統內部資料。
