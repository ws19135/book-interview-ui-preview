# 新書訪談邀約｜情境操作體驗（第二階段）

給公司同事試用、留回饋的**靜態互動示意稿**。

👉 **[打開試用](https://ws19135.github.io/book-interview-ui-preview/BOOK_INTERVIEW_UI_M0_WIREFRAME.html)**
👉 **[同事試用說明](COLLEAGUE_UI_REVIEW_GUIDE.md)**（10–15 分鐘）

## 這一版做了什麼

依 **Ivy（總經紀人）2026-09-04 的試用回饋**重整流程與畫面。

- 原本 15 個細步驟 → **整併成 8 個業務階段**
- 每個階段**只呈現一個主要任務、只有一個主要按鈕**、顯示「第 N ／ 8」
- 資料**預先填好**，多數步驟按一下就完成
- ⛔ 不再讓測試者先選「情境／自由操作／對照」等模式
- ⛔ 工程測試工具（重複送出、版本衝突、拒絕頁）**移出主要旅程**

## 八個階段

```
1 建立需求與指定承辦   →  2 推薦適合的節目      →  3 處理費用或例外審核
4 給需求方確認推薦節目 →  5 記錄節目邀約回覆    →  6 確認製作方與訪談時間
7 追蹤錄音、上架與素材 →  8 完成案件並查看歷程
```

## 依 Ivy 回饋調整的重點

| Ivy 提到 | 這一版 |
|---|---|
| 提出需求後由誰接手？怎麼通知需求人？ | 階段 1 顯示承辦人，並模擬「已接手，處理中」通知 |
| 現況是經紀人推薦節目，作者許願會有收費問題 | 階段 2 由經紀人從清單挑；偏好節目改標「僅供評估，不代表保證安排」 |
| 不知道去哪挑節目？清單在哪？ | 階段 2 給**可點選的節目清單**，⛔ 不再手打 |
| 名單要加推薦原因與是否需付宣傳費 | 階段 2／3／4 都顯示推薦原因與費用 |
| 審核由誰做？目的是什麼？ | 階段 3 **只在付費或例外時出現**，並用白話說明為什麼 |
| 節目回覆由誰回？ | 階段 5 明說節目方不登入系統，由承辦人記錄 |
| 建議先給三個可訪談時間讓對方選 | 階段 6 支援一次提出**最多三個時段**，再記錄確認的那一個 |
| 素材只要確認收到公關書就好 | 階段 7 公關書預設「本案必要」，其餘「建議提供」；結案**只擋本案必要** |
| 按了查看就隱藏不起來 | 階段 1 加「重新隱藏」，換頁與重新載入也會**自動遮回** |
| 加入候選節目／推薦名單看不懂 | 改成「加入推薦節目」「推薦節目清單」「記錄節目回覆」 |

## 回饋機制

- 每一階段一個選填欄位「這一步哪裡看不懂？」，**步驟名稱自動帶入**
- 中途輸入標示為**草稿**；最後四題只有走完全部階段才出現
- ⛔ 沒有嚴重度欄位（舊版會沿用上一則，導致 14 則全同一級）
- 只寫瀏覽器本機儲存，**永不上傳**；Markdown／JSON 真正下載
