# 新書訪談邀約｜情境操作體驗

給公司同事試用、留回饋的**靜態互動示意稿**。

👉 **[打開試用](https://ws19135.github.io/book-interview-ui-preview/BOOK_INTERVIEW_UI_M0_WIREFRAME.html)**
👉 **[同事試用說明](COLLEAGUE_UI_REVIEW_GUIDE.md)**（15–20 分鐘）

---

## 這是什麼

試用的人扮演 **公司內部負責新書宣傳與訪談邀約的企劃**。

```
林以安老師剛出版《在變動裡，找到自己的節奏》。
你需要替老師建立新書訪談需求，挑選適合的 Podcast／節目，
記錄邀約回覆，安排訪談與所需素材，最後完成案件。
```

**起點是自己點進功能入口，不是收到一封公開表單。**
打開後先看角色說明 → 按「開始情境測試」 → 在功能入口頁自己點「新書訪談邀約」 → 進入工作總覽 → 十五步走完整件事。

| 有 | ⛔ 沒有 |

| 公開安全掃描腳本 | 任何對外連線或追蹤碼 |

**產品本體在另一個 private repo，不在這裡，也不會被複製到這裡。**

## 硬規則

1. ⛔ 完全沒有對外呼叫——沒有遠端請求、沒有長連線、沒有 CDN、沒有外部字型。
2. ⛔ 不連任何資料庫。所有操作只在瀏覽器記憶體裡，重新整理即重置。
3. 只有你填的**回饋**會寫進瀏覽器本機儲存，且**永不上傳**。
4. ⛔ 沒有 GitHub Actions、沒有分析工具、沒有第三方資源。
5. ⭐ 主要操作流程裡**不出現工程術語**；技術細節一律收進頁尾的「設計與驗證備註」，預設收合。

發布前必須跑：

```bash
python3 scan-public-safety.py .
```

七項全綠（credential／identifier／email／URL／絕對路徑／網路呼叫／後端原始碼外洩）才可以發布。

## 三個模式

| 模式 | 用途 |
|---|---|
| **情境式操作體驗**（預設） | 十五步跟著走，就像真的在承辦這件事 |
| **自由操作** | 沒有步驟指引，隨便按；也可以看需求方那端的表單長什麼樣（不接送出） |
| **整件事的全貌** | 系統預定涵蓋的完整流程，每一段標了做到什麼程度 |

頁尾的 **「設計與驗證備註」**（預設收合）放給專案負責人看的技術細節：
詞彙對照、情境起點的裁決、現況／後續對照表、訪談案件動作與實機的對齊、已知問題。

---

## 訪談案件的動作已對齊實機

⛔ 沒有通用的「更新製作進度」下拉——實機是逐個獨立按鈕：

```
設定製作方 · 訪綱完成 · 排程（提出／確認／改期）
標記已錄音 · 標記已剪輯（僅公司製作）· 交給對方上架（僅對方製作）
標記已上架（需填連結）· 不予上架（僅公司製作，需填原因）
談定金額 · 暫緩／回復 · 一般結案 · 一般取消
```

結案前系統會逐項檢查六件事（邀約結果、必要素材、訪綱、錄製、上架、例外原因），
逐條對齊實機的結案檢查，未過會直接列出缺什麼。

## 排版

字級走 token，**最小 13px**：

```css
--font-xs: 13px;   --font-sm: 14px;   --font-base: 15px;  --font-md: 16px;
--font-lg: 18px;   --font-xl: 22px;   --font-display: 28px;
```

色彩取自實機（米色底 `#ECE6DB`、襯線標題、細線分隔、赭紅重點色 `#B5451F`），
⛔ 無圓角、⛔ 無陰影、⛔ 無單邊粗色條。
⚠️ 字級比實機大——這份是給同事在各種螢幕上讀的，可讀性優先。

## 假資料規則

- Email 一律 `@example.invalid`
- 編號一律 `REQ-DEMO-001`／`CAS-DEMO-001`／`MAT-DEMO-001` 這種格式
- 人名、書名、節目名稱全部虛構
