# 新書訪談邀約系統 · UI 預覽

給 Owner 與同事查看、點擊、留回饋用的**靜態互動示意稿**。

👉 **[開啟預覽](https://ws19135.github.io/book-interview-ui-preview/BOOK_INTERVIEW_UI_M0_WIREFRAME.html)**
👉 **[同事測試說明](COLLEAGUE_UI_REVIEW_GUIDE.md)**（15–20 分鐘）

---

## ⚠️ 這個 repo 裡有什麼、沒有什麼

| 有 | ⛔ 沒有 |
|---|---|
| 一份單檔 HTML 示意稿 | 產品原始碼 |
| 全部編造的假資料 | 任何真實資料或個資 |
| 同事測試說明 | 任何識別碼、網址、金鑰、憑證 |
| 公開安全掃描腳本 | 任何對外連線或追蹤碼 |

**產品本體在另一個 private repo，不在這裡，也不會被複製到這裡。**

---

## 這份預覽的硬規則

1. ⛔ 完全沒有對外呼叫——沒有遠端請求、沒有長連線、沒有 CDN、沒有外部字型。
2. ⛔ 不連任何資料庫。所有操作只在瀏覽器記憶體裡，重新整理即重置。
3. 只有你填的**測試回饋**會寫進瀏覽器本機儲存，且**永不上傳**。
4. ⛔ 沒有 GitHub Actions、沒有分析工具、沒有第三方資源。

發布前必須跑：

```bash
python3 scan-public-safety.py .
```

七項全綠（credential／identifier／email／URL／絕對路徑／網路呼叫／後端原始碼外洩）才可以發布。

## 兩個模式

**模式 A · 目前已完成** —— 忠實呈現現行版本**已經存在**的畫面。
沒做的東西不會出現在這裡。頂端只有 4 個入口（工作總覽／需求清單／主檔／稽核查閱），
需求詳情、名單確認、訪談案件、素材完整性都是從需求清單**往下鑽**——這和實機一致。

**模式 B · 完整流程藍圖** —— 系統預定的 15 段生命週期，
每一段標了「證據到哪裡」（live 驗證／僅 R2／僅本機／尚未多角色／Phase 2／不在範圍）。

**現況／Roadmap 對照** —— 12 個畫面逐列比對：實際部署了什麼、live 看到什麼、這份 Demo 做了什麼、還缺什麼。

## ⚠️ 這份預覽證明不了的事

- 靜態 Demo 全部通過 **⛔ 不等於**產品 runtime 通過。這裡沒有伺服器、沒有資料庫、沒有權限檢查。
- 多角色（不同職務）真人操作 **⛔ 尚未執行**。
- 需求方點確認連結的對外關卡 **⛔ 尚未有真人走過**。
- 正式環境 **⛔ 未授權、⛔ 未部署**。

本輪定位：**UI／流程驗收**。⛔ 不是權限、安全、資料正確性或正式上線驗收。

## 假資料規則

- Email 一律 `@example.invalid`
- 編號一律 `REQ-DEMO-001`／`PER-DEMO-001`／`CAS-DEMO-001` 這種格式
- 人名、書名、節目名稱全部虛構

## 視覺

配色與字級逐項對齊實機：米色底（`#ECE6DB`）、襯線標題、細線分隔、赭紅重點色（`#B5451F`）、
⛔ 無圓角、⛔ 無陰影、⛔ 無浮誇卡片。
